# ADR-0019: Промпт в snapshot'е — неизменяемое СОДЕРЖИМОЕ, закреплённое хэшем (T7.35, §8.7.1, §12, §14)

Статус: accepted

Дата: 2026-09-23

## Определение

Промпт в конфигурационном snapshot'е — это **неизменяемое содержимое,
закреплённое хэшем**: запись `prompts.<role>` payload'а несёт
`path` (относительно корня репо), `version` (ярлык из заголовка
`version:` файла) и `sha256` (хэш сырых байтов файла). Загрузчик
резолвит промпт **по ссылке из snapshot'а** (путь из payload, а не
зашитое имя файла), сверяет заголовок версии **И** sha256 содержимого;
при любом расхождении — fail-closed: сессия не стартует, причина
записывается в audit (`prompt_pin_mismatch`, out-of-session event).
Каждый вызов модели записывает `model_runs.prompt_version` (ярлык) и
`model_runs.prompt_sha256` (содержимое, которое реально ушло модели);
fingerprint вызова включает оба.

Это приведение реализации к уже существующей спецификации, а не новая
функция: `payload_sha256` — «canonical hash immutable
model/embeddings/**prompts**/policy/…» (ARCHITECTURE.md:1215, 2069);
fingerprint «включает также prompt version» (ARCHITECTURE.md:1719);
`model_runs` хранит `prompt_version` (ARCHITECTURE.md:1886).

## Что было не так (найдено при приёмке T7.34)

1. **Ярлык вместо содержимого.** Payload хранил
   `prompts.<role> = {"path": "prompts/<role>.md", "version": "<ярлык>"}`;
   `protocol_hash` хэшировал этот dict (memory/service.py:398) — то
   есть ярлык. «Замороженные payload'ы v2…v5 не тронуты, хэши сверены»
   защищало ярлыки, а не поведение.
2. **Игнорируемый путь.** `load_prompt` читал `PROMPTS_DIR / f"{role}.md"`
   с диска: путь из payload не использовался (имя файла зашито в код).
3. **Нет сверки.** Версия бралась из заголовка файла и НИКАК не
   сверялась со snapshot'ом — fail-closed проверки не было. Любой прогон
   на любом payload'е молча грузил то, что лежало на диске кода.
4. **Пустой prompt_version.** `model_runs.prompt_version` был пуст у
   ВСЕХ 620 вызовов в noezema-eval4d и noezema-eval3d: оркестратор
   передавал версию в fingerprint, но ни одна из 8 точек записи
   `ORMModelRun(...)` поле `prompt_version` не заполняла.

### Улика расхождения (до правки)

Активные snapshot'ы EVAL-4d (payload'ы v4/v5) объявляли
`curator-v2/explorer-v2`, а bootstrap-snapshot, записанный кодом в том
же прогоне (миграция 0001 пересчитывает pin из кода), показывает: на
диске тогда были `curator-v3/explorer-v4` (BOOTSTRAP_PAYLOAD после
T7.14/T7.21). Файл `prompts/curator.md` на HEAD до T7.34 — curator-v3,
после T7.34 — curator-v4.

baseline EVAL-4d) шли с промптами curator-v3 (+ explorer-v3/v4), а не с
объявленными curator-v2/explorer-v2. EVAL-1/2/3b — с объявленными
v2/v2 (совпадение).

## Решение

1. **Привязка по содержимому (п.3 T7.35).** `resolve_prompts`
   (packages/llm_gateway/roles.py) — резолвит каждую роль payload'а по
   его ссылке (`path` относительно корня репо; зашитого имени больше
   нет), сверяет sha256 сырых байтов файла с пином и заголовок версии с
   объявленным ярлыком. Любое расхождение → `PromptPinError` →
   fail-closed: сессия не стартует, в admission-транзакции пишется
   audit `prompt_pin_mismatch` (session_id NULL — сессия не создана),
   запись admission НЕ регистрируется. Защита от path traversal (путь
   обязан оставаться в пределах корня репо), неизвестные/отсутствующие
   роли — тоже fail-closed.
2. **model_runs (п.2).** Все 8 точек записи `ORMModelRun` теперь
   заполняют `prompt_version`, `prompt_sha256` (новая колонка,
   миграция 0025) и `tool_schema_hash`; fingerprint вызова
   (build_model_fingerprint) включает `prompt_version` И
   `prompt_sha256`. Исторические строки сохраняют `prompt_sha256 =
   NULL` (до пинов); их фактические тексты — в таблице криминалистики.
3. **Исторические тексты доступны (п.3).** Раскладка
   `prompts/<role>/<version>.md` — одноимённо версии, байт-в-байт из
   git (`git show <коммит-актуальности-версии>:prompts/<role>.md`):
   curator-v1…v4, explorer-v1…v4, planner-v1, verifier-v1,
   extractor-v1 (11 файлов; sha256 каждого зафиксированы тестом
   `test_historical_prompt_files_match_git_blobs`). **Единый источник
   истины — версионированные файлы**: плоские `prompts/<role>.md`
   удалены (их содержимое — те же байты в версионированных копиях;
   старые пути живут в git-истории). Двух расходящихся копий нет:
   payload пинит ровно один файл, loader читает только его.
4. **Непинованные payload'ы v2…v5 (и v6) — решение (б): fail-closed,
   запуск отказывается.** Обоснование:
   - (а) «резолвить по объявленной версии в восстановленный файл»
     вернул бы исполнимость payload'у, который НЕ фиксирует
     содержимое — именно тот класс молчаливой неопределённости,
     который закрывает ADR-0019: payload'ы v2…v6 хэшируют ярлык, и
     гарантия воспроизводимости для них была бы выдуманной;
   - при (а) v4/v5 давали бы curator-v2/explorer-v2 — НЕ то, что
     реально шло в EVAL-4d (таблица выше): «перезапуск EVAL-4»
     молча менял бы промпты на противоположные от истории;
   - v6 также непинован — под (а) он дал бы explorer-v2, хотя все
     прогоны с T7.21 шли на диске с explorer-v4;
   - культура системы — fail-closed (AGENTS.md §3, effective config),
     и «payload без пина содержимого не исполняемый» — честное
     состояние, а не уязвимость.
   Следствие: закоммиченные файлы v2…v6 остаются артефактами (никогда
   не переписываются), но исполняемым payload'ом с этого момента может
   быть только пинованный (v7+). Исторический текст не переписывается.
5. **Новый пинованный payload — v7** (`docs/eval/config-v7-payload.json`
   = v6 + `sha256` содержимого всех промптов; v6 закоммичен T7.34 и не
   переписывается). Всё, кроме `prompts`, — байт в байт v6.
   `TokenBudgets.validate() == []`. canonical sha256 v7:
   `b1c572bdad7d413983412c1ec867db27f869f34f74d117a488dba2a29ebe8207`.
   ВНИМАНИЕ: v7 пинит **explorer-v2** — версию, объявленную v6;
   текущий explorer на диске — v4. Если смоук-прогон нужен на
   explorer-v4, это отдельное решение о СОДЕРЖИМОМ (новый payload
   v8) — не в пределах T7.35 (задача про привязку, не про содержание).
6. **BOOTSTRAP_PAYLOAD (паттерн T7.14, теперь по содержимому).** Пины
   всех пяти ролей: explorer-v4 (5829a55c…), curator-v4 (6e129ded…),
   planner-v1 (6aeb22bc…), verifier-v1 (34fe8069…), extractor-v1
   (af5dba62…), пути — версионированные файлы. Миграция 0001
   пересчитывает hash из кода (fail-closed) — новые БД получают
   пинованный bootstrap; существующие (замороженные) БД не трогаются,
   admission сверяет `BOOTSTRAP_SNAPSHOT_ID` (UUIDv5, не меняется), а не
   содержимое.
7. **protocol_hash** (memory/service.py:398) без изменения формулы:
   хэш dict `prompts` snapshot'а теперь транзитивно включает пины
   содержимого — идентичность окружения отражает реальное содержимое.

## Последствия

- **Сопоставимость прошлых прогонов:** итоги EVAL-1…EVAL-4d остаются
  валидными для ТЕХ прогонов (сохранённые данные не трогались), но
  сравнения «EVAL-X vs payload'ы, которые он якобы использовал»
  невалидны: серии 3c/3d/4 шли на curator-v3/explorer-v3|v4, а не на
  объявленных v2/v2. Пометки добавлены в EVAL-3-freeze.md,
  EVAL-4-freeze.md, ADR-0008 (исторический текст не переписан).
- **EVAL-5:** заморозка недействительна — она стоит на payload'ах
  v4/v5 (непинованных; при решении (а) дали бы v2/v2, а не то, что шло
  в EVAL-4d). Перезаморозка НЕ выполняется в T7.35 (впереди корпус
  v5): перед запуском EVAL-5 нужна перезаморозка на payload'е с пином
  содержимого (v7+). Пометка — в начале EVAL-5-freeze.md.
- **Смоук-прогон:** ближайший — на config-v7-payload.json.

## Что НЕ меняется

- rules_hash, claim_type_rules, пороги §22.2 и направления гейтов;
- закоммиченные payload'ы config-v2…v6 (файлы не переписаны —
  сверить: docs/eval/config-v{2..6}-payload.json);
- корпуса v1–v4;
- сохранённые данные прошлых прогонов (noezema-eval* — SELECT only);
- ТЕКСТ промптов: curator-v4 остаётся curator-v4 — задача про
  привязку, не про содержание;
- ARCHITECTURE.md — не тронут: спека уже требует неизменяемые
  промпты в payload'е (1215/2069), prompt version в fingerprint'е
  (1719) и prompt_version в model_runs (1886) — T7.35 приводит
  реализацию к спеке, правка спеки не потребовалась;
- формула `protocol_hash` (содержимое dict теперь честнее — см. п.7).

## Известные ограничения

- Исторические `model_runs` (все 620+ строк прошлых ранов) остаются с
  пустым `prompt_version` и `prompt_sha256 NULL` — перезапись
  сохранённых прогонов запрещена; фактические тексты восстановлены
  криминалистикой (таблица выше) и версионированными файлами.
- Путь в payload'е — относительно корня репо; загрузчик принимает путь
  из payload'а, а не из кода, но корень (REPO_ROOT) — константа кода:
  перенос репо в другое место без версии git не поддерживается
  (развёртывание — всегда из git).
- Файл, чей sha256 совпадает с пином, но чей заголовок другой,
  отклоняется (двойная сверка); порядок проверок: sha256 → заголовок —
  подмена содержимого всегда видна по хэшу.

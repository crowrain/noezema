## Как добавлять новый ADR (сложившаяся практика)

- Новое архитектурное решение или осознанное отклонение от спеки — новый файл
  `docs/adr/NNNN-kebab-имя.md`, номер — следующий по счёту (четыре цифры). Решение требует
  явного согласия пользователя (AGENTS.md §4); это зафиксировано в STATUS.md задачи, которой
  ADR внесён.
- Формат файла: первая строка `# ADR-NNNN: Заголовок`; далее контекст (со ссылками на пункты
  `ARCHITECTURE.md`), разбор вариантов, решение и следствия. Явная строка статуса обязательна
  (older files — `Статус: accepted`; newer — `- Статус: принято/пропоновано`).
- Статус эволюционирует явными дописками, принятый текст не переписывается: уточнения и
  частичные принятия добавляются разделами вида «Уточнение T7.NN (дата)» в конец файла
  (прецеденты: ADR-0004→ADR-0015, ADR-0029 §18–§20, ADR-0034 §9, ADR-0036 §1а/§1б). Частичное
  принятие называется по частям (ADR-0027, ADR-0031).
- Если решение меняет payload конфигурации — изменения описываются в AGENTS.md §6 (цепочка
  конфигураций с canonical-хэшами); если меняет поведение витрины или гейтов хоста — тесты и
  их имена указываются в STATUS.md задачи.
- После внесения ADR добавить строку в этот индекс: номер со ссылкой на файл, заголовок как в
  файле, статус как в файле, одна строка сути.
